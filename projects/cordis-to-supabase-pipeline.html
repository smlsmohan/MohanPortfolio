A portable Python ETL flow that prepares cleaned CORDIS project data for the web application. The pipeline was created after moving away from trial-dependent Fabric-only processing, so the core data preparation can run locally and load the final web dataset into Supabase.

Purpose

The pipeline keeps the project independent from temporary cloud trials. It prepares the final web dataset using Python so the data can be rebuilt and loaded again whenever the Supabase project or hosting setup changes.

Pipeline Flow

Download or reuse source files→Extract→Transform→Gold outputs→Web dataset→Supabase load

Key Work

  • Standardised programme values across FP7, H2020 and Horizon Europe.
  • Improved country mapping and reduced unknown country labels.
  • Generated Gold-style fact and dimension outputs including policy priority, publications, deliverables and organisation facts.
  • Created a web-optimised `cordis_projects` table for fast search and dashboard use.
  • Added validation checks for row counts, duplicate IDs, blank programme/status values and unknown country rows.

Outcome

The pipeline now supports the live CORDIS Research Explorer application and gives a repeatable path to rebuild the final cleaned data without depending on a Fabric trial account.
